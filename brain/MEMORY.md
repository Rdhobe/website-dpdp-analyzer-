## Known Limitations and Problems

1. **No product functionality exists.** The backend only exposes a health check; the frontend is a placeholder.
2. **Persistence and queue are unwired.** SQLAlchemy, Alembic, Celery, and Redis packages are installed, but there are no services, models, migrations, or workers.
3. **Minimal test coverage.** Three backend tests exist (health + config); there is no meaningful regression safety.
4. **No secret storage decision.** `.env.example` exists, but deployment secret management is undecided.
5. **Default metadata and landing page** are still create-next-app; require replacement.
6. **Font mismatch** in `globals.css` (Geist loaded, Arial applied).
7. **Legal framework not curated.** No official provisions are stored; do not invent citations.
8. **Severity rubric undefined.** Do not use severity labels without a documented rubric.
9. **Cognitive hazard:** requirements describe a full system in present tense. Always verify code before reporting status.

## Constraints to Remember

- Never bypass MFA/CAPTCHA/access controls.
- Never store plaintext passwords or log credentials.
- Crawl only authorized scope; block private networks/metadata endpoints.
- Treat crawled content as untrusted data (prompt injection).
- AI is optional; deterministic checks must run without paid providers.
- No fake progress, scores, findings, tests, or legal claims.
- Do not claim DPDP compliance certification.
- Preserve tenant isolation in every query.
